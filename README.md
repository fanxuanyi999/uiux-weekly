# 快爆 UI/UX 周报

`content/issues/YYYY-MM-DD.json` 每期一份公开稿。首页提供正文阅读，长文可以在原地展开。独立归档页支持按日期浏览、全文搜索和主题筛选。

本地运行 `npm ci` 后执行 `npm run dev`。发布前执行 `npm run validate` 和 `npm run build`。推送到 `main` 后，GitHub Actions 构建并发布到 GitHub Pages。默认地址使用仓库名作为路径前缀。

## 每周采编

1. 按北京时间周五日期创建文件。先读历史期次以去重，再从公开来源独立选题。优先收集国内成熟 App 和产品设计团队关于 AI 赋能、项目协作、组织分工与能力建设的实际案例，也关注设计调研、体验优化、设计还原和验收提效。
2. 确认每篇原文的发布日期、实践及其结果，区分实际案例、实验与提案。选 3–5 条，补充值得借鉴的海外实践。遇到主题重复时，只收录有新做法或新证据的案例。符合要求的资讯不足 3 条时先补找来源，无法补足就说明具体问题。
3. 每条在 `paragraphs` 中写至少两段自然正文，把核心发现、应用价值和可执行的动作写具体。在 `publisher` 和 `url` 填发布方和直接来源，在 `focus` 写一项团队可试的实验。内部项目与非公开资料不进入公开稿。
4. 校验后只提交当期文件到 `main`。检查 Actions 和面向读者的网页，再报告本期发布成功。已有相同期次时先确认线上结果，避免重复提交。
